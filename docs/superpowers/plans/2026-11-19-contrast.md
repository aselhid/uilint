# Contrast Rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `contrast` rule that reports text, input values and placeholders whose WCAG 2.x contrast against the rendered background is too low, and says "not checked" (with the reason) when the background can't be known.

**Architecture:** The measure script optionally stashes each box's DOM element and text nodes on `window`. After the stable snapshot (and the report screenshot), `captureContrast` evaluates `contrast.page.js`, which hit-tests sample points with `elementsFromPoint` and returns the raw colour layers below each one. Node composites those layers (exact group opacity) and computes ratios in pure, unit-tested TypeScript, then attaches `box.contrast`. The `contrast` rule turns that into findings; the report tags them.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), Playwright/Chromium, vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-contrast-design.md`

## Global Constraints

- No new runtime dependencies; don't touch `package.json` name/publish fields.
- With no contrast problem, stdout, JSON and exit codes stay exactly as today. With `contrast: 'off'` the contrast pass doesn't run at all.
- In-page scripts are single self-contained function expressions, plain JS, no imports, no trailing `;`.
- WCAG 2.x: `(L1+0.05)/(L2+0.05)`, linearisation threshold 0.04045; no rounding when comparing; printed ratios truncated to 2 decimals.
- Large text: font-size ≥ 24px, or ≥ 18.66px with weight ≥ 700. AA: 4.5 / 3. AAA: 7 / 4.5.
- Rule options and defaults: `level: 'AA'`, `ratio: 'error'`, `placeholder: 'error'`, `unverified: 'warn'`; rule default severity `error`.
- Messages: `text contrast 2.85:1, needs 4.5:1 (#999999 on #ffffff)`; `… needs 3:1 for large text (…)`; values `input text contrast …`; placeholders `placeholder contrast …`; gradients `(#999999 on #f5f5f5, worst gradient stop)`; unverified `text over an image, contrast not checked` (reason-specific wording, Task 5).
- Report labels: `2.85:1 · min 4.5:1`; unverified `not checked: image`.
- Only existing test edited: `tests/unit/rules-index.test.ts` registry list gains `'contrast'` (adding a rule necessarily changes it).

## Review Focus

1. Text over a positioned sibling (hero `<div>` behind `<h1>`), not an ancestor → must use the sibling's colour (Task 3 test `positioned sibling background`; clean fixture in Task 6).
2. Body background propagated to the canvas when `<html>` has none and the body is shorter than the viewport → base is the body colour (Task 3 test `body background propagates`).
3. Tailwind v4 `oklch()` colours → converted, not treated as unparseable (Task 3 test `oklch colours`).
4. Text below the first viewport → measured, and the page's scroll position is restored (Task 3 test `below the fold`).
5. `opacity` on a parent that has an opaque background → exact group compositing, not alpha multiplication (Task 1 test `group opacity`, Task 3 test `opacity on a parent with a background`).
